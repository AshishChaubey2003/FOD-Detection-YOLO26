A. OVERALL ERROR ANALYSIS
A1. Both error types are large. [MEASURED] 3825 of 6721 GT objects are missed (56.9%); 4117 of 7013 retained predictions are false (58.7%). Precision and recall are therefore both limited (~0.41 and ~0.43).
A2. Where errors concentrate [COMPUTED]. Top FP classes: Screwdriver 663, Washer 380, Wrench 370, PlasticPart 351, PaintChip 321. Top FN classes: Wrench 523, Pliers 480, Wire 287, PlasticPart 276, MetalPart 213. Zero-TP classes with GT: Hammer, LuggagePart, Nail, Pen, Pliers. Eight classes (AdjustableClamp, AdjustableWrench, BoltNutSet, Hose, MetalSheet, Screw, Tape, Wood) have no test GT, so every prediction on them is FP by construction; this does not prove the model can never detect them.
A3. Validation-to-test gap [PROVIDED val values, test values from Step 13]. Val -> test: Precision 0.558 -> 0.380, Recall 0.473 -> 0.426, mAP50 0.477 -> 0.367 (-0.110, -23.1%), mAP50-95 0.393 -> 0.252 (-0.141, -35.9%). The drop suggests the model generalizes less well to the test split than validation indicates.
A4. Why the gap alone does not prove overfitting [HYPOTHESES]: (a) the best epoch (23) was chosen on validation, which biases validation upward; (b) the test split has 8 classes with zero GT while class mix differs from validation; (c) official evaluation arguments are unrecovered; (d) test and validation images may differ in distribution. Separating overfitting from split differences needs train/val/test comparison on the same classes and metric, and learning curves.
A5. mAP vs fixed-threshold TP/FP/FN. mAP integrates the precision-recall curve over all confidence levels; TP/FP/FN at conf 0.25 reflect one operating point. [MEASURED on test, corrected mapping] lowering the threshold from 0.25 to 0.001 raises recall from 0.4309 to 0.6989 but drops precision from 0.4129 to 0.0987; raising it to 0.75 gives precision 0.5076 and recall 0.258. Many correct detections therefore exist at low confidence, and a single fixed threshold penalizes them.

  2. PaintChip <-> PlasticPart (both directions): FP 004563 (PaintChip pred overlaps GT PlasticPart, IoU 0.867) and FN 024416 (GT PaintChip, PlasticPart pred conf 0.872, IoU 0.971). Class level: PaintChip 186 GT, 22 TP, 321 FP.

C. OBJECT SIZE AND LOCALIZATION
- [MEASURED] BoltWasher 001415 (~9.3 x 7.7 px) is a TP (conf 0.821, IoU 0.774), and BoltWasher is a strong class (P 0.947, R 0.887). Tiny size alone therefore does not explain failure.
- [COMPUTED] The missed examples are large: Hammer 019176 270.8x230.1 px, Pliers 017872 169.7x262.4, Wrench 018701 201.1x128.8, PaintChip 024416 162.3x249.3. For these, class discrimination or annotation/definition issues look more relevant than size [HYPOTHESIS].
- [COMPUTED, illustrative arithmetic, not measured detections] A perfect box shifted by 2 px diagonally has IoU 0.410 for a 9.3x7.7 object, 0.863 for 49.9x57.2, and 0.931 for 86.6x155.7. At IoU 0.50, small boxes are very sensitive to small localization errors, so a visually close prediction can become both an FP and an FN.
- Images are natively 300x300. Enlarging them adds no new information and is not guaranteed to help; this must be tested. No size-binned recall analysis over all GT was performed, so no overall size effect is claimed.

- A single threshold may not suit all classes [HYPOTHESIS]: in two examples the correct same-class prediction had very low confidence (Pliers 0.006, Wrench 0.032) while a wrong-class prediction was confident (0.819, 0.646). Class-wise confidence behaviour was not measured; it needs validation-based calibration.
- Safety: a missed object (FN) can leave debris on the runway; a false alarm (FP) costs inspection time and can cause alert fatigue. A screening role would likely favour high recall with human verification, but the operating point must be set on validation data against an explicit safety requirement.
- Status: [MEASURED] tested threshold = 0.25. [RECOMMENDATION] future experiments: per-class thresholds chosen on validation. [UNVERIFIED] any specific new threshold; none is recommended here. Even at conf 0.001, recall is 0.6989, so a large share of objects is still missed.
- Human verification is mandatory in any operational use; this model must not be deployed as an autonomous runway safety system.

E. WEATHER, LIGHTING AND DATASET LIMITATIONS [PROVIDED Step 4b statistics; arithmetic verified]
- Dry 26,577 (78.65%), Wet 7,216 (21.35%); Bright 16,942 (50.13%), Dim 12,464 (36.88%), Dark 4,387 (12.98%); Fog absent.

- No per-condition test performance was computed, so no error is attributed to weather or lighting.
- Unresolved: the leakage-neighbour audit (whether adjacent frames fall in different splits) was deferred and not run. If near-duplicate frames cross splits, test metrics may be optimistic [HYPOTHESIS, unverified].

F. PRIORITIZED IMPROVEMENTS (details in improvement_roadmap.csv; expected benefits are hypotheses, not results)
1. Class-level data/label audit and rebalancing for zero-TP and confusable classes. Problem: 1124 GT in 5 zero-TP classes; confusable pairs above. Experiment: count per-class training instances, review annotation/class definitions for the pairs, add varied examples or class-aware sampling, retrain on the same splits. Measure: per-class recall/precision/F1 and mAP50 on validation, confusion off-diagonals, then one final test evaluation. Risk: labels may be intrinsically ambiguous; rebalancing may hurt strong classes.
2. Validation-based per-class threshold calibration and stronger evaluation. Problem: one threshold (0.25), unrecovered official config. Experiment: save all eval arguments, compute per-class PR curves on validation, choose operating points for an explicit recall target, freeze, evaluate once on test with bootstrap confidence intervals. Risk: thresholds may not transfer; small per-class validation counts.
3. (Conditional) Small-object/resolution/tiling experiment. First measure recall by GT-size bin on existing predictions; only if small objects are shown to limit performance, ablate larger input size and tiled inference against the baseline. Risk: compute/latency, no extra detail beyond native 300x300, tile-merge duplicates.
